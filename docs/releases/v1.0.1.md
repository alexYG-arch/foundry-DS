# Harness Foundry v1.0.1

产品版本 **1.0.1**，协议版本 **2.9**，MIT 许可。`v1.0.1` 标签固定本次源码。

本版接受 `a3-read-v2` 修复分支的完整导入。导入不是把分支补丁伪装成独立
产品，而是把已审查的 A3/A4 修复、控制视图、可靠性修复和文档状态源合并为
一个可构建源码基线；旧 v1.0.0 及更早标签、Release 和附件保留。

## 本版范围

- `ControlViewV2`：先取 revision，再以 `up_to_revision` 固定授权/尝试读取；
  使用与派发边界相同的授权链判定，支持 Plan 1.3 的可选来源绑定。
- `read-build --control-view`：只读、机器可读的控制事实入口，不加载
  source/proposal 正文，不授予派发权限。
- dedup 写入与迁移：内容随 append 事务提交，不再共享实例状态；批处理迁移
  保留 event/revision/idempotency 身份并在目标库执行 VACUUM。
- 热路径：`_current`/`advance`/readback 对来源正文改为按 event ID 点读；
  `list_events_by_types` 支持 revision 上界和类型索引工具。
- Plan/Scope 1.3：共享投影、控制器标签和 verifier 根绑定与 1.2 机械保证对齐。
- 文档与状态：`docs/STATUS.json` 是门禁数字和计划状态的单一来源；
  `docs/DOC_INDEX.md`、路线图和发布文档引用它而非各自复制数字。
- 源码门禁按平台拆分：Linux 不再因缺少 macOS seatbelt 而结构性失败；
  同一平台集合内仍禁止 skip 计通过。

## 不包含

- 活动 8.5GB 数据库迁移/切换。用户已明确将其移出本版闭合范围；离线迁移工具
  和验证属于本版，真实活动库不在本版操作。
- 真实原生模型端到端、完整兼容矩阵、物理 sibling 规范核验、同包双案例、
  干净提交发布构建、发布上传等项。未执行项在门禁报告中标为 `NOT_RUN`，不
  以静态测试替代。
- GUI attach、2A macOS VM、70 次实验等外部门。

```text

```

包由 `devtools/package_generic_release.py` 从当前固定源码组装；它不是
release acceptance receipt，也不包含活动库、项目数据、凭据或本地运行日志。

## 升级边界

源码已修、固定包已包含、目标项目实际部署已升级是三个不同状态。升级应使用
独立目录和明确版本，保留旧控制库、证据和累计预算；不复制旧 `.venv`，不把
本 Release 当作既有项目的自动迁移。
